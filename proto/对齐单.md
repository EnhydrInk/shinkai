# 原型对齐单

## 已完成与契约

- TypeScript + 官方 MCP SDK `1.32.1`，Streamable HTTP，单进程共享一张桌；没有 stdio、前端或模型 API 调用。
- 默认 4 人、起手 3 张、最多 10 轮、60 秒超时。支持 2–4 人，参数集中在 `config/default.json`。
- 四种颜色与数字牌，功能牌为跳过、反转、+2、变色；功能牌可配置删减。
- 入座取得随机 token；查询、等待和行动全部按 token 验证座位。局面仅含自己的手牌、公共顶牌／颜色／方向／剩余张数／当前玩家和自己的合法出法。
- `joinKey` 为私密入座恢复凭据；相同名字和 key 可安全重试。名字或座位号不能用于取回 token。凭据仅存于内存，不输出到服务端日志。
- `wait_for_my_turn` 最多等 25 秒，返回 `your_turn`、`waiting` 或 `finished`。满员自动开局；等待和错误操作不刷新回合截止时间。
- `act` 必须附当前 `turnId`；非法出法返回原因和自己的新局面。旧回合、重复、并发重复行动最多生效一次。
- 后台计时器自动罚摸并换人，无需客户端查询触发；迟到的行动同样先结算超时。服务器重启会结束内存中的牌局。
- 每一步记录开始时间、行动时间和毫秒延迟；结束输出平均、最慢一步、最慢一轮、完整步骤和轮次。日志不包含手牌或 token。
- `RoomOptions.onPublicEvent` 提供公开事件出口；`GameEngine.applyExternalAction` 预留外部动作入口，当前明确拒绝执行。均未接人类功能牌或 webhook。

## 启动与开 AI 局

在 `proto/` 内：

```sh
npm ci --cache .npm-cache
npm run check
npm start
```

共享地址：`http://127.0.0.1:3333/mcp`。只启动一个服务进程。

- [README](README.md)：两种 CLI 的完整连接命令；Claude 按次加载 HTTP JSON，Codex 按次传 HTTP URL 和 40 秒工具超时。
- [玩家 prompt](docs/PLAYER_PROMPT.md)：直接分别交给四个独立会话。
- [默认配置](config/default.json)：规则参数；改完重启。
- `npm run build` 后可运行 `node dist/src/main.js`。
- 本次自测进程已关闭，没有留下占用端口的服务。开始真实对局时重新 `npm start`；再开两个 Sonnet 和两个 Codex。

## 验收结果

测试环境：Node.js `25.9.0`，npm `11.12.1`；最低目标 Node.js 22 尚未单独实测。

- 类型检查通过，编译通过。
- 测试 **27/27**：规则引擎 **23** 项，HTTP／等待生命周期 **4** 项。
- HTTP 验证覆盖两个独立 SDK 客户端共享状态、跨座位读取失败、外人牌不能出、非法出法返回重试信息、并发重复行动、等待唤醒、断线后 token 恢复、Host／Origin 校验。
- 等待时限测试用可控计时器验证：24999 毫秒仍未返回，25000 毫秒返回 `waiting`。
- 编译产物启动验证通过：健康检查、MCP 初始化、入座、默认配置（4／3／10／60000）、SIGTERM 正常退出。
- Codex 按次配置经过本机 `mcp get tabletop --json` 解析：`streamable_http`，工具超时 40 秒。Claude 命令及参数经本机帮助核对。
- 免费 bot 自测 **4/4**，模型 API 调用 **0**。每局使用真实 HTTP 和四个官方 SDK 客户端，随机选择服务器返回的合法出法。

| 场景 | 结束方式 | 有效步骤 | 自动超时 | 全局耗时 ms | 平均一步 ms | 最慢一步 ms | 最慢一轮 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 四个随机 bot | 清空手牌 | 18 | 0 | 118 | 4.39 | 8 | 27 |
| 完整十轮 | 轮数上限 | 40 | 0 | 185 | 4.28 | 8 | 22 |
| 一个座位全程不回应 | 轮数上限 | 40 | 10 | 1509 | 37.02 | 122 | 157 |
| 全员沉默、无人轮询 | 两轮上限 | 8 | 8 | 274 | 31.00 | 32 | 124 |

完整数字、随机种子、配置、最慢步骤和轮次见 [artifacts/selftest.json](artifacts/selftest.json)。每次重跑会覆盖报告，耗时会浮动；上表为交付时的一次实测。

加速配置：普通 bot 局超时 1000 ms；单座位沉默局 120 ms；全员沉默局 30 ms。完整十轮和单座位沉默局关闭提前清空结束，以确保跑满 40 步。默认服务配置仍为 60000 ms。

受控故障验证：在隔离副本中禁用后台计时器，只运行全员沉默场景，将检测期限缩短为 1 秒；自测按预期以 exit 1 失败。正式实现没有此故障。全员沉默场景在结束事件出现前不调用查询工具。

这些毫秒数是本地随机 bot 的耗时，**不是模型思考延迟**。两种真实 CLI 同桌对局尚未执行。

## 待确认的规则细节

以下为原型暂定语义，尚未取得最终规则确认：

- 一轮 = `seats` 次有效行动（含超时），跳过和罚摸不额外计步；反转不改变轮长。
- 默认清空手牌立即胜出；可用 `stopOnEmptyHand:false` 改为始终打到上限。到点按手牌张数，最少者并列共同获胜。
- 摸一张后结束回合；默认允许有可出牌时自愿摸牌。没有摸牌后当回合再出的阶段。
- +2 立即罚摸并跳过，不叠加；两人局反转默认相当于跳过；最后一张功能牌先结算效果再结束。
- 功能牌可按相同牌面跨色接；起始牌只用数字牌；变色牌任意时刻可出。
- 牌堆耗尽后回收弃牌并保留顶牌；无牌可回收时摸牌不增加手牌，仍换人。
- 最慢一轮包含提前结束的末轮，并通过 `complete:false` 标识未满轮。

已配置的变化点见 README 的参数表；上述其余语义若改变，需要调整引擎及对应测试。

## 剩余验证和明天接入点

1. **真实模型局**：两个 Sonnet + 两个 Codex；验证各 CLI 的工具权限、25 秒长轮询、模型持续循环和真实延迟。模型可用性、账号额度及 Dot 的具体接入协议未验证。
2. **Dot 通知**：接 `src/room.ts` 的 `onPublicEvent`。`turn_started` 现有字段为 `seatId / turnId / deadline`，结束事件含胜者和计时。适配层负责座位与 Dot 身份映射、签名、投递及重试；不要在公共事件内塞手牌或 token。接收方仍凭座位凭据查询私有局面。实际 MCP Events webhook 的字段／鉴权／重试约定需以明天拿到的接口为准。
3. **公网和共享状态**：当前为本机单进程，未部署。需要选定房间状态归属、持久化与可靠超时调度；多实例必须共享并串行更新同一房间。Workers 方向可用官方 SDK 的 Web Standard HTTP transport 并接持久房间；Vercel 方向也需外部共享状态与调度，不能只搬现有内存 Map。平台运行时和长请求限制未验证。
4. **人类功能牌**：扩展 `src/engine.ts` 的 `ExternalAction / applyExternalAction`，定义经授权的具体命令和规则，再加独立入口；现阶段未开放工具。
5. **公网身份**：本机 token 做了手牌隔离，但未做玩家身份／房间邀请／防抢座／速率限制。知道某座位 token 或 joinKey 的人具有该座位权限。公网接入需同时调整 HTTPS、Host／Origin 配置与身份绑定。

## Review 与交付顺序

- 代码、测试、报告、玩家说明在 `proto/` 的本地 commit；不 push。
- 无数据库迁移或部署步骤；本地验收顺序为安装依赖 → `npm run check` → 启动单个服务 → 四个客户端入座。
- 克先生 review 规则暂定项、手牌边界、超时调度与迁移接口；review 通过后再进入推送／部署。
